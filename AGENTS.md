## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. APIs you remember are likely renamed, moved, or removed. Before writing any code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt — an index of all Expo docs with corrections to common LLM misconceptions. Follow its links to the specific page you need; never answer from memory.

## Commands

Use `bunx` instead of `npx` if the project uses bun (`bun.lock` present).

```bash
npx expo install <package>  # ALWAYS use instead of npm/yarn/pnpm/bun add — resolves SDK-compatible versions
npx expo start              # start the dev server
npm run typecheck           # tsc --noEmit
npx prettier --check .      # formatting (config in .prettierrc.json)
npm run assets              # regenerate recipe covers, emoji icons and app icons
npx expo-doctor             # diagnose dependency and config issues
npx expo install --fix      # fix incompatible package versions
```

Run the typecheck and Prettier before declaring any task done.

## Navigation & Routing

- This app uses **React Navigation 7** directly (not Expo Router), so the web build never touches the URL and runs inside sandboxed previews.
- `src/navigation/RootNavigator.tsx` holds the root native stack. Onboarding screens and the main app are two conditional groups switched by `useAppStore().onboarded`. Screens reused from the profile have their own route names (`EditMarket`, `EditBudget`, …) so finishing onboarding leaves no stale routes behind.
- Tabs (`Plan`, `Recipes`, `Community`, `List`, `Profile`) use the custom `src/navigation/TabBar.tsx`. Route params are typed in `src/navigation/types.ts`.
- The profile editor is registered twice: `CreateProfile` (onboarding step 1) and `EditProfile` (main group). Community screens (`PostDetail`, `UserProfile`, `Composer`) live in the main group.

## Project layout

- `src/data/` — static catalog: markets (price index), ingredients (BRL prices, aisle, nutrition), recipes, appliances. `emoji.ts` and `covers.ts` are generated by `scripts/generate-assets.mjs`.
- `src/lib/` — pure logic: pricing and tags (`recipes.ts`), plan generation and budget fitting (`planner.ts`), aisle-sorted shopping list (`shopping.ts`), TikTok/Instagram import and pt-BR ingredient parsing (`importer.ts`).
- `src/store/` — zustand store persisted with AsyncStorage, plus memoized selectors.
- `src/social/` — community feature. `SocialBackend` (`types.ts`) has a local demo implementation (`demo/`, seeded examples) and a Supabase one (`cloud/`); `backend.ts` picks Supabase when `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` are set. Screens use the React Query hooks in `hooks.ts` and `usePostActions.tsx`. `convert.ts` turns posts into `Recipe`s (`post:<id>`) so they work in the planner and shopping list.
- `supabase/migrations/` — community schema, RLS policies, counter triggers and the `recipe-photos` bucket. Change the schema with a new migration file, never by editing an applied one.
- Posts/recipes show per-step quantities through `src/components/recipe/` (`ingredientRows.ts` matches ingredient names inside each step).
- `src/screens/`, `src/components/`, `src/theme/` — UI. All user-facing text is Brazilian Portuguese.
- Import icons from `src/components/icons.ts` (one lucide file per icon) instead of `lucide-react-native`, which would bundle every icon.

## Building with EAS

Use EAS to build, sign, and submit the app in the cloud (`eas build`, `eas submit`) and to ship over-the-air updates (`eas update`) — no local Xcode or Android Studio required. Run EAS CLI as `bunx eas-cli <command>` in Bun projects, or `npx eas-cli@latest <command>` otherwise; substitute that for bare `eas` in docs examples.
Docs: https://docs.expo.dev/eas/index.md

## Rules

- If `ios/` and `android/` directories do not exist, they are generated (Continuous Native Generation). Never create or edit them by hand — configure native behavior in `app.json` and config plugins.
- Expo Go only includes its bundled native modules. After adding a library with native code, the app needs a development build: `npx expo run:ios|android` locally, or `eas build --profile development`.
- Prefer recommended Expo modules over third-party libraries, and check your available skills before adding dependencies. Docs: https://docs.expo.dev/versions/latest/index.md
